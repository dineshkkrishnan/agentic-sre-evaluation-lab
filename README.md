# Agentic SRE Evaluation Lab

An evaluation harness for **incident recommendation outputs**, with synthetic cases, a deterministic baseline and an optional local Ollama adapter. No recommended actions are executed.

## Why evaluate first?
A plausible diagnosis can still cite nonexistent evidence or propose an unsafe operation. This lab scores diagnosis, action eligibility and evidence contracts separately. It gives failures full weight and compares candidate outputs against a simple baseline.

## Quick start
Python 3.11+; the offline evaluator uses the standard library only.

```bash
python3 evaluate.py
python3 evaluate.py --predictions data/unsafe_fixture.json --output output/unsafe_report.json
python3 -m unittest discover -s tests -v
```

See [baseline report](examples/baseline_report.json) and [unsafe-fixture report](examples/unsafe_report.json). Fixture outputs are hand-authored, not generated by an LLM. The baseline deliberately fails the missing-citation case: a positive signal without evidence is insufficient under that case's rubric.

## Optional actual model inference
Install and run Ollama separately, with a model already downloaded. Then:

```bash
python3 ollama_adapter.py --model YOUR_INSTALLED_MODEL
python3 evaluate.py --predictions output/ollama_predictions.json --output output/model_report.json
```

The adapter calls only `http://127.0.0.1:11434/api/chat`, uses structured JSON output and never sends grading labels. Network/inference errors are recorded as invalid predictions, not dropped. No real model benchmark has been run for the published example. The adapter is covered by prompt-construction tests; live inference requires your local model and may take time/resources.

[Official Ollama chat API](https://docs.ollama.com/api/chat).

## Prediction contract
JSON list with one record per case: `case_id`, `diagnosis`, `action`, `evidence_ids`. Optional `latency_ms` must be finite and nonnegative. Diagnosis/action vocabularies live in `evaluate.py`; unsupported output fails schema grading. Duplicate/unknown case IDs reject the batch; missing case outputs count as failures.

## Metrics and limits
- Diagnosis accuracy: exact label match across **all dataset cases**.
- Disallowed-or-invalid action rate: actions outside the case allowlist, invalid schema or missing output.
- Evidence-contract pass rate: cites only supplied evidence IDs and includes the required IDs.
- Overall pass: all three checks pass.
- Latency: median of reported values, with coverage shown. External timings are unverified; baseline timings measure only its function call.
- Cost is **unknown/null**, not zero. The adapter records model token counts when available; it does not estimate hardware cost or dollar pricing.

Evidence-ID checks do not prove semantic grounding, detect arbitrary unsupported prose or measure hallucination in general. Eight small synthetic cases are a smoke-test rubric, not a representative benchmark. Expected labels are curated lab assumptions. The suite contains prompt-injection strings, but cannot certify broad injection resistance.

## Leadership decisions this makes reviewable
Define a rubric before inspecting a model's outputs. Decide how to handle abstention, missing evidence and disallowed actions. Compare to a baseline and report failures rather than cherry-picking successes. Keep approval/enforcement separate from recommendations.

## Next experiments

A real multistep tool-using agent is future work: this first version evaluates single recommendations.
